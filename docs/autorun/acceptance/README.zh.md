## f. "颜色改为三档、取代计分"让哪类记录变了色

做法：拿同一批最终运行的标识，按原型的计分规则重算一遍颜色。原型规则见 `scratch/prototype/rules.yaml`：每个标识按 points 累计，满 3 分转人工；`alone` 单独出现即转人工。

- 原型里属于计分类的标识，用原型的分数；
- 按决定新加的标识（税、Delta 不一致、查重等）不在原型里，计作单独转人工。

所以下表只反映"三档 vs 计分"本身造成的差别。

| 集 | 颜色变化的记录 | 原因（标识） |
|---|---|---|
| A | 4 条：计分下是解析通过检查，现在是建议人工审核 | 模型自报疑问 3 条，"合计与各项对不上"1 条：单独出现时原型只给 2 分，不到 3 分 |
| B2 | 3 条：同上 | 模型自报疑问 3 条 |
| mock | 86 条：解析通过检查 → 建议人工审核 | "其他"代码 65 条（mock 里大量费用名不在代码表）、模型自报疑问 20 条、"计入金额是空格拼出来的数"1 条 |
| mock | 1 条：建议退回 → 建议人工审核 | 模型自报疑问 |

**结论**：
- 三档只会让颜色更"保守"（多送人工），不会让任何记录少一个标识。
- 变色集中在三类标识上：模型自报疑问、"其他"代码、合计对不上。
- 其中"其他"代码是决定 3.7 要求打标识的，"模型自报疑问"是决定 2.3 要求作为规则输入的；它们单独就送人工，是三档的直接后果。
- 影响大小：真实数据上（A、B2）影响 3 到 4 条；mock 上很大，因为 mock 的费用名大多不在代码表里。
- 模型自报疑问在重复运行中只有 57% 稳定，所以由它单独决定颜色，会让同一条记录的颜色在不同运行之间变化。
- 是否改回计分，或把这两类降为提示，列在待决 P-14。
