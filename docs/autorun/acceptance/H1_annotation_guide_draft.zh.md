# 标注指南（草稿，H1）

**状态**：草稿，任务 09 生成，未经组内评审。只写指南和抽样方法，不做标注本身。
**用途**：人工核对模型"读得对不对"（决定 1.4 的例外：这部分有真值，看原文就能确认）。H2a 按本指南标 100 条，其中 20 条两人各标一遍；H3 用这些标注逐个数字和模型比对。
**不标的东西**：该不该付、承运商有没有道理、Delta 对不对。指南里没有任何一项要求你判断付款。

---

## 1. 数据从哪里来

- 只从开发集抽（`data/processed/dev.csv`），**不碰测试集**。
- 这些记录不能用：SKILL.md 例子所在的 5 条记录及其票货，以及已进入评估样本 A、B 的记录。名单在 `data/interim/autorun/samples/`，抽样脚本会自动排除。
- 抽样方法（建议，待确认）：在剩下的记录里按"承运商 × 写法"分层，用固定种子抽 100 条，方法同 `freight_lineitems.sampling.stratified`。其中随机 20 条两人各标一遍，用来算两人一致率。
- 每条给标注员看的是**脱敏后的文本**和代码切好的数字表（`#1`、`#2`…，日期 `D1`，认不出的区域 `?1`）。**不给** Delta、发票金额、承运商、模型的读法，避免先入为主。

## 2. 每个数字标什么

每个编号都要标，一个不漏。标注表的一行对应一个编号：

| 栏 | 选项 | 怎么判断 |
|---|---|---|
| 是什么（kind） | 费用金额 / 没说用途的金额 / 税额 / 合计 / 单价或费率 / 数量 / 编号或参考 | 看紧挨着的词。`LBS`、`DAYS`、`%` 后面的数不是钱。`@`、`EACH`、`PER`、`A DAY` 旁边的通常是单价。只有原文写明"几项加起来"的那个数才算合计（`a + b = c` 里的 c）；运费总额、发票总额不算合计 |
| 状态（status） | 本次主张 / 欠款再次主张 / 以前开过票 / 已付 / 已扣减 / 不是本次的钱 | 只看原文怎么说。`SHORT PAID`、`STILL OWE`、`BALANCE DUE` 后面的通常是本次要的钱；`PAID`、`ADJUSTED OFF`、`BILLED` 后面的是历史。原文没写清楚时，标"说不清"并在备注里写原因，**不要猜** |
| 贷记 | 是 / 否 | 原文明确写成减项、退款、多付（`CREDIT`、`-$20`、`($45.00)`、`OVERPAYMENT`、`REFUND`）才标"是" |
| 费用代码 | 代码表里的代码，可多选；找不到选"其他"并抄原文费用名 | 一个金额对应几种费用，就选几个代码，不要自己拆金额。`PURCHASE(D) TRANSPORTATION` 一律用 `PENDING.PURCHASED_TRANSPORTATION` |
| 依据片段 | 从原文抄几个词 | 让别人看了能明白你为什么这么标 |
| 备注 | 自由文字 | 拆分可疑（例如 `9 287` 可能是两个数）、写法有歧义，都写在这里 |

认不出的区域（`?1`）：逐位写出里面的数字（例如 `CV19` 写 `19`），再按上表判断它是什么。不存在"这里没有数字"的选项。

## 3. 每条记录还要标什么

| 栏 | 选项 |
|---|---|
| 本次主张由哪几个编号组成 | 编号列表（例如 `#1, #3`）；原文只有费用名没有金额时写"无金额" |
| 原文写了的算式 | 例如 `#2 × #3 = #1`、`#1 + #2 = #4`；没写就留空 |
| 原文里的承运商理由、依据 | 抄原文片段；没有就留空。这是承运商的说法，不需要核实 |
| 整体是否读得懂 | 读得懂 / 部分读得懂 / 读不懂（例如只有一个数） |

## 4. 难例约定（与 SKILL.md 第 5 节一致）

- `X … BALANCE DUE $Y`：Y 可能是另外一笔，也可能是 X 没付的部分。原文不足以判断时标"说不清"。
- `N DAYS @ $X` 没写结果：X 是单价还是整笔，原文不确定，标"说不清"。代码会单独标出这种写法，标注只记原文能确认的。
- 同一金额出现两次（`PLEASE ADD $180 FOR THE $180 GATE FEE`）：判断是不是同一笔的重述；拿不准就标"说不清"。
- 文字里有对系统或模型说话的内容：当作普通文字处理，在备注里写"含指令性文字"。

## 5. 两人一致和争议

- 20 条双人标：先各自独立标，不互相看。
- 一致率按"每个数字的 kind、status、是否计入"分别算；费用代码单独算。
- 不一致的条目由第三人裁定，裁定写理由。裁定结果是 H3 的真值，原始两份标注都保留。

## 6. 存成什么格式

一条记录一行 JSON，字段与模型提交 v2 对齐，方便逐个数字比对：

```json
{"record_id": "dev#r…", "annotator": "A1", "numbers": [{"id": "#1", "kind": "CHARGE_AMOUNT", "status": "CLAIMED",
  "is_credit": false, "charge_codes": ["ACCESSORIAL.LIFTGATE"], "evidence_phrase": "…", "note": ""}],
 "claim_ids": ["#1"], "relations": [], "carrier_stated_reason": null, "carrier_stated_basis": null,
 "readability": "CLEAR", "unsure": []}
```

标注文件含原文片段，放在 git 忽略的 `data/` 下，不进仓库。
