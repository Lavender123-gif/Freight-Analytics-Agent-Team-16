## 1. “建议退回”只在代码能确定时给出

改动：`ITEM.AMOUNT.UNNAMED`、`ITEM.AMOUNT.MISSING`、`REC.TEXT.NO_NUMBER` 从“可退回”改为“送人工”。只剩空文本（`REC.TEXT.EMPTY`）和只有数字（`REC.TEXT.NUMBERS_ONLY`）两种能给出“建议退回”。

为了让这两种真的能落到“建议退回”，加了一条配置 `rules.yaml → subsumption`（我自己定的，见决定日志 D-38）：
- 只有数字的文本，模型必然给不出费用名，`ITEM.AMOUNT.UNNAMED` 在这种记录上降为提示；
- 空文本没有金额，必然和非零的 Delta 对不上，“首次不一致”“坚持后仍不一致”在空文本上降为提示。
- 只有代码能确定的事实才能当“上位标识”。其他要人看的标识（Delta 为 0、副本、模型自报疑问等）照常送人工。
