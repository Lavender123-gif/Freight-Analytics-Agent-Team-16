## 2. 第 A 部分：业务调研（自上而下）

用网上公开资料做调研。**搜索词里不得出现任何客户数据**（承运商名、地址、金额、文字原文、PPG 内部编号都不行）。每条结论注明来源和可信度（行业标准文件、厂商文档、行业文章、论坛）。

**A1. 审核员确认每一类费用时看什么。**以 `taxonomy.yaml` 里的主要类别为单位（至少覆盖开发集里出现频率最高的类别，以及滞留、搬卸、空驶、压车过夜、改派、燃油附加费），逐类写：
- 业内核实这类费用通常要什么证据（例如滞留费的到达和离开时间、免费时长；搬卸费的收据；空驶费的取消时间）。
- 这些证据里，哪些可能出现在承运商的文字里。

**A2. 容易被滥用或出错的费用类别。**只作为类别层面的信息，供审核界面提示"这类费用通常需要核实什么"，不对单笔费用下"可疑"的结论。

**A3. 评价承运商的常用指标**（例如附加费占运费的比例、争议率、发票准确率、重复提交率）。只用来确定 **schema 里要存哪些字段**才能算出这些指标；不计算、不打分、不做承运商评分功能，这是下游的事。

**A4. 现有标准和开源方案。**先看行业已有的数据结构，以它们为基础，不从头发明：
- X12 EDI 210（承运商运费发票）的结构，以及通用的附加费代码。
- Oracle OTM 公开文档里发票、发票明细、附加费的数据模型。
- GitHub 等开源社区里有没有运费审计、发票对账相关的成熟 schema。
- 逐项对比这些方案和我们需求的差异：哪些可以直接用，哪些要改，哪些没有。

## 3. 第 B 部分：数据关系（自下而上，只用开发集）

**B1. 各个编号之间的关系。**在开发集上弄清 `SHIPMENT_GID`、`PK`、`Invoice/Bill ID`、`Carrier Invoice`、原始行之间是一对一、一对多还是多对多，各给出数量分布。

**B2. "一笔争议挂在多个 PK 下"这种情况。**决定记录第 4.6 节描述了用户在原始数据里看到的一例。在开发集上统计：
- 文字、Delta、时间完全相同，只有 PK 不同的组有多少，每组大小的分布。
- PK 编号日期晚于争议时间的情况有多少。
- 之前合并掉的 45 行"导出纯重复"用的是哪五个字段，这类组有没有被合并。如果没有，说明 908 这个数和 01b 的统计受了多大影响（只说明影响，不重算 01b）。

**B3. 重复的成因和特征。**按决定记录第 5.2 节的三个层面，总结数据里可能产生重复的原因，每种写出可以识别它的特征。**不看 `Invoice Dups Removed` 这一列。**任务 05 已有结论的直接引用。这一部分以后用来造 mock。

**B4. 国家与币种。**统计起讫省州推出的国家和 `US/CAN` 这一栏不一致的比例。

**B5. 计算 CO 金额占比需要的字段**（例如 Delta 和运费）在数据里是否都可靠。

## 4. 第 C 部分：schema v0

从 A 部分的需求出发，用 B 部分的数据关系落地，参考 A4 的现有标准。

**C1. 表的划分。**每张表写：存什么、为什么需要、主键、和其他表的关系。起点可以参考下面这个草稿，但按调研和数据结论修改，改了要说明理由：
- 票货；承运商发票；账单记录（PK）；原始行（Excel 每一行原样保留，带来源文件和行号）；争议（我们理解的一笔争议，关联到它出现过的所有原始行）；费用明细；模型的每次尝试；标识；审核员的决定。
- "原始行"和"争议"必须分开：前者忠实于 Excel，后者是我们的理解。

**C2. 每个字段**写：含义、类型、读者（审核员、下游系统、我们自己的审计和评估）、来源（Excel 原样、代码推算、模型判断、审核员决定）、能否为空及条件。没有读者的字段不要放。

**C3. 多层面查重落在哪里。**每一层的检查读哪些字段、标识存在哪张表、怎么指向"第一份"、跨批次时怎么找到之前的那份。

**C4. 留痕。**模型的哪些判断要存、存在哪里、给谁看。至少覆盖：每个数字的解读、整笔主张金额、算式关系、费用代码和依据片段、排除金额的理由、每次尝试的内容和与 Delta 是否一致、修改时模型给出的理由、前后两次尝试的差异、模型主动报告的疑问。每一项说明它服务于哪个读者；没有读者的不存。

**C5. 依赖客户回答的部分**标 `[待 Jake]`，并写上决定记录第 8 节里对应的问题编号（例如 J1）。

**C6. 存储方式**给一个建议（例如 SQLite），标"建议，待确认"。JSON 导出格式从表结构推出，给一个示例即可。

**C7. 机器可读的版本**：把 schema 另存一份 YAML（或 SQL DDL），放在 `docs/analysis/06_schema_v0.yaml`，供以后实现时使用。
