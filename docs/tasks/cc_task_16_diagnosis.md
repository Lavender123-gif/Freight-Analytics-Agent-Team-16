## 1. 问题来源的分类（先写后提交）

下面每一处"送人工""可疑""FN""FP""差异"，都归到一个主来源，可以另记一个次来源：

| 来源 | 含义 |
|---|---|
| 输入本身的问题 | 承运商文字本身有缺陷：空、只有数字、有金额没写费用名、写了税种没写税额、按标准确实说不清 |
| 历史关系 | 同一票货里的重复、取代、相同金额、BALANCE DUE |
| 模型读错 | 文字按我们的标准是清楚的，模型的读法和标准不同 |
| 模型读法偏差 | 同一类写法，模型一贯读成某一种，和标准不同（模型读错的系统性版本） |
| 规则没覆盖 | 现有规则和阅读约定都没说怎么处理 |
| 实现没触发 | 规则要求提醒，代码没有触发 |
| 规则文字有歧义 | 规则文字有两种读法，实现选了一种，规则文字没跟上 |
| 标准答案和我们的规则冲突 | 人工标注或 mock 答案与我们写下的决定不一致 |
| 标注一方缺信息 | 标注人当时没有某项信息，例如代码表，或后来才定的规则 |
| 脱敏影响 | 遮挡改变了模型看到的文字 |
| 安全 | 注入 |
| 其他 | 写明是什么 |

## 3. 标准答案和系统的系统性差异

**定义（先写后提交）**：同一类写法上，标准答案（人工标注或 mock 答案）和系统一贯朝同一个方向不同，算系统性差异。门槛：mock 上同一组至少 5 条，人工标注上至少 3 条。偶发的单条不同不算。

**做法**：
1. 逐字段比较：是不是金额；计入、不计入、贷记；费用大类；说明合计；建议。
2. 按写法特征分组。先写好特征清单再看结果，至少包括：BALANCE DUE；EARLIER、PRIOR、PREVIOUS、PAID 一类表示历史的词；税种词；`@` 或 PER；以点开头的小数；代码表里没有的费用名；一个金额对应多项费用；脱敏占位符。
3. 每个达到门槛的组写：
   - 哪套数据、条数、方向（谁算计入、谁算不计入，或谁选了哪个类别）；
   - 差异发生在哪一步：模型读法、代码规则、票货汇总；
   - 原因：第 1 节的来源之一；
   - 按我们写下的标准哪边对；标准没说的，写"需要用户定"；
   - 如果按对的一边纠正，对 Recall、FOR、Precision 的影响。
4. **用真实数据做旁证**：mock 上找到的每个系统性差异组，到开发集全量里找同样的写法：真实数据里有多少条，系统怎么读的，其中有多少在标注集里、标注人怎么标的。
5. 已知要覆盖的几组（不是全部，要查全）：标注人的费用类别和代码表口径不同；BALANCE DUE 写在最前面；P-10 那类写法；代码表里没有的费用名；一个金额对应多项费用；注入词被脱敏遮掉。
