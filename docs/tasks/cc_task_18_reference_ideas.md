# 任务 18 参考想法（抛砖引玉，不是结论）

**在完成并提交任务 18 第 4 节之前，不要打开本文件。**

这些是用户和 Claude 讨论中形成的初步想法。请用你扫出来的数据逐条检验，同意、不同意都要写理由。

## 1. 总体形态

代码前处理 → 模型步骤（skill 加工具）→ 代码后处理，颜色由规则算。必须每条记录都执行的逻辑放在代码里，不做成模型可以选择调不调用的工具。

## 2. 现在唯一那个 SKILL.md 的问题

- 所有内容每次一起塞进提示词。
- 有过时的内容：仍在讲"和记录上的调整金额比较"和 `inconsistent` 回执，这些已经撤掉了。
- 有些概念在 SKILL.md 和规则代码里各定义了一次，例如 BALANCE DUE。
- 改任何一句都影响所有记录，所以每次调优都要全量重跑。

## 3. 按"活"分 skill，至少两个

划分原则：输入、输出、运行时机不同，就是不同的活，用不同的 skill；同一件活里的不同专题，做成同一个 skill 里的参考文件，由代码按特征决定附加哪些。

- **skill A：读一条说明。** 输入是一条说明和它的数字表；输出是这一条的字段（每个数字是什么、算不算这次要的钱、费用类别、承运商的理由、说明里写出的算式）。税、数量乘单价、费率和合同更正、贷记、代码表、安全，是 skill A 里的参考文件。说明里提到"更早的主张"一类的话，skill A 只标出"提到了更早的主张"，不去猜它算不算这次的钱。
- **skill B：读一票货的历史。** 只对有两条以上说明、或说明里有历史用语的票货运行。输入是这票货按时间排好的各条说明原文，加上 skill A 对每条的读法（以后可加上更早批次里这票货的记录）。输出是说明之间、费用之间的关系，每条带原文证据：重述前一条的某项费用、是前一条某项费用的余额、另加一笔、引用了这批里找不到的更早主张、说不清。可能需要的工具：查这票货的历史记录、比较两笔金额、找历史类的例子。
- 其他可能的模型任务（给审核员写说明、提议代码表新增项）是否单独成 skill，属于范围决定，由用户定。

## 4. 分工原则

- skill 只判断"文字说了什么、是哪种关系"，不算总额。
- "重述就只算一次、另加就相加"这类约定，只在规则代码里定义一次，由代码算总额和颜色。
- 代码能确定的事实（订单号相同、文字完全相同的副本）由代码判断。
- skill B 的判断和代码现有的表面特征（同一代码、1.03 到 1.07 倍、相同金额）不一致时，打提醒送人工。
