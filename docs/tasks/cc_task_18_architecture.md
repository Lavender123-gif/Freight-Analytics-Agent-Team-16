## 3. 摸底（用数据）

1. **流程清单**：从读入 Excel 到审核界面，每一步写：做什么、在哪个文件和函数、由谁决定（代码、模型、工具、人）、是否每条记录都执行。
2. **`SKILL.md` 逐节**：放了什么；哪些句子已经过时（和现在的代码不符）；哪些在规则代码或 `rules.yaml` 里也有定义，两边是否一致；每节大约多少 token。
3. **工具调用统计**（从已保存的对话记录算）：每个工具在开发集全量和 mock 第三轮上被调用多少次、多少条记录用过、平均每条几次、报错和参数无效各多少次；只调用 `submit_line_items` 就结束的记录占比；调用了某个工具的记录，和"读错、自报疑问、送人工"之间有没有关联（只描述，不下因果结论）。
4. **按特征分组**：按代码能检测的特征（税种词；BALANCE、PAID、BILLED 一类；`@`、PER、EACH、DAYS；FSC SHOULD APPLY、PER CONTRACT 这类费率更正写法；CREDIT、负号；EARLIER、PRIOR、REVISED、REBILL 一类历史用语；注入词），统计开发集全量和 mock 第三轮上各组的说明数，以及同时落在几组的分布。
5. **多说明票货**：开发集全量和 mock 第三轮上，有两条以上说明的票货数、说明里有历史用语的票货数；现在汇总代码里处理跨说明关系的每条规则，各触发多少次，在 mock 第三轮上各有多少漏报和误报。
6. **出错集中在哪**：用任务 15 到 17 已有的漏报和系统性差异结果，按上面的分组归类；特别标出哪些漏报是因为模型一次只读一条说明、看不到同一票货的其他说明。

## 4. 独立设计（在打开参考想法之前完成并提交）

1. **系统要做的每一件事**：输入、输出、是否需要理解文字、是否每条记录都要做、做错的后果。
2. **归层**：每件事归代码、工具、skill（哪一个 skill，核心还是参考文件）或人，写理由。
3. **划分 skill 的原则**：先把原则写出来，再按原则给出 skill 清单。每个 skill 写：输入、输出、什么时候运行、包含哪些知识、需要哪些工具、和代码规则的分界、用什么数据评估。
4. **工具的目标集合**：每个工具保留、合并、修改还是新增，理由来自第 3 节的统计。不少于 5 个，且每个都有实际用处。
5. **一处定义**：每个业务概念（例如取代、相加、余额、重复）的唯一出处。

写完后**先提交一次**，提交信息写"T18 独立设计"。
