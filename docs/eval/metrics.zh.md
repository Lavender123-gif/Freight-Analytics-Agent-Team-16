# V1 指标定义和报告模板

脚本：`scratch/eval/metrics.py`。只衡量“读得准不准”，不涉及费用该不该付。所有输出只有汇总数，不含原文和编号。

## 1. 对照人工标注（`annotations` 子命令）

输入：一次管道运行的 `data/interim/runs/<run_id>/records.jsonl`，以及 `scratch/annotation/import_annotations.py` 写出的长表（一行是一个标注人对一个数字的答案，列见该脚本开头）。逐个数字比较，用运行的**最终读法**。

| 指标 | 单位 | 人工一侧 | 模型一侧 | 算一致的条件 |
|---|---|---|---|---|
| 是否金额 | 数字 | 第 1 项是否选“金额” | kind 属于费用金额、未说明用途的金额、税额、合计 | 两边相同 |
| 计入、不计入、贷记 | 数字 | 第 2 项归为三类；不是金额的数字算不计入 | 费用类 kind 且状态为本次主张或欠款：计入（带贷记标记为贷记）；其余不计入 | 三类相同 |
| 费用大类 | 两边都计入的数字 | 第 3 项 | 费用代码所属大类；没有代码时，税额算“税”，其余算“原文没写费用名” | 人工选的大类在模型给出的大类之中 |
| 主张金额合计 | 记录 | 计入的金额相加，贷记相减 | `mock_eval.signed_sum`（同样规则） | 两个合计相等 |

单独报告、不计入上面分母的：

- **人工选“说不清”的数字**：给出个数，以及模型在这些数字上各选了什么。含“说不清”的记录不算主张金额合计。
- **标注人之间有分歧的数字**（只出现在公共记录上）：合并口径下不评分，按字段给出个数。
- **覆盖情况**：标注过但不在这次运行里的记录数；标注包和运行的数字切分不一致的记录数（两边代码版本不同，不比较）；没有模型读法的记录数（主张金额合计按不一致计）。

口径：

- **合并口径**：只有一个人标的数字用这个人的答案；多人标的数字，全体一致才用。
- **分标注人口径**：每个标注人自己做的全部记录各算一遍。
- **标注人之间的一致率**：公共 15 条上两两计算，逐项给一致率和 Cohen's κ（`scratch/annotation/agreement.py`），与上面的结果并排打印。模型与人的一致率要对照这个数来读：人与人都达不到的水平，不能要求模型达到。

## 2. 公开 mock（`mock` 子命令）

直接调用 `scratch/autorun/mock_eval.py` 的 `score`（主张金额正确数、首次读法正确数、建议与预期一致数、注入事件的报告数、读错的失败类型），再加上三种建议在整次运行里的分布（条数和占比）。建议取自运行输出里保存的结果；规则改动后要先重算再看分布。

## 3. 自检（`selftest` 子命令）

用运行自己的读法加随机噪声生成假标注，再评分。噪声为 0 时各项必须是 100%。只证明脚本能跑通，**不是结果**，不写进任何报告。

## 4. 数据使用规则

- 开发集和公开 mock 可以反复使用，用于开发和调优。
- **预留 mock 批次只用一次**：只在最终测试时评分一次，评分之后不再根据它修改提示、规则或代码。本脚本的 `mock` 子命令只读公开 mock。
- 测试集不在本脚本的输入之内；是否用测试集做标注包由项目负责人决定并亲自运行。
- 门槛在跑之前写进状态卡片的完成标准，跑完不改。

## 5. 报告模板

```
标注：<文件>          标注人数：N     统计时间：<起止>
覆盖：标注记录 a 条，进入比较 b 条，不在运行中 c 条，切分不一致 d 条

                         一致 / 总数    一致率    事先写定的门槛
是否金额                  x / n         xx.x%     ≥ ..
计入、不计入、贷记         x / n         xx.x%     ≥ ..
费用大类                  x / n         xx.x%     ≥ ..
主张金额合计（按记录）      x / n         xx.x%     ≥ ..

人工“说不清”：m 个数字（模型选了：计入 a、不计入 b、贷记 c）；涉及 k 条记录，不算合计
标注人分歧（不评分）：是否金额 a、计入与否 b、大类 c
混淆（人工>模型）：……

标注人之间（公共 15 条，两两）：
字段    标注人对    个数    一致率    κ

公开 mock：事件 n，主张金额正确 x（xx.x%），建议与预期一致 y
三种建议分布：解析通过 a（..%）、建议人工 b（..%）、建议退回 c（..%）
```
