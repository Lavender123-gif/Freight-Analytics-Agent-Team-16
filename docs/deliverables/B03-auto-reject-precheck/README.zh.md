# B03 打回预判

## 这一块做什么
在第 2 步之后、调用模型之前，判断一条争议是否应该直接自动退回承运商（02 D4）。触发条件全部由代码判定：文本为空，或文本只有数字没有任何文字。豁免条件：同一票货**更早**（Event Date 严格更早）有一条 Delta 相同、写了费用名称的记录。命中且不豁免时**不调用模型**，直接生成给承运商的自动通知，通知文字全部取自诊断目录（C1）。

## 输入和输出
- 输入：第 1、2 步的诊断，同一票货更早的记录（文本、Delta）
- 输出：处置（`AUTO_REJECT` 或继续），自动通知（修改要求、合格标准）
- 代码：`scratch/prototype/pipeline.py`（预判分支）、`history.py`（预判模式）、`disposition.py`、`rules.yaml` 的 `auto_reject`（原型，未改动）

## 一条命令复现
```
sh scratch/deliverables/run.sh B03_auto_reject_precheck.py
```
结果写到 `results/summary.md`、`results/examples.md`；每条事件的处置在 git 忽略的 `data/interim/deliverables/B03/`。

## 检验数据
开发集全量：908 条事件（953 行），不是测试集；另有 3 个合成用例检验豁免规则和"只看更早记录"。数字与 02 §7.3 对照。

## 结果
- 8 项检查和 3 个合成用例 **全部通过**。
- 自动打回 10 条事件（15 行）：只有数字 6 条、空文本 4 条，与 02 §7.3 一致；这 10 条都没有调用模型，都生成了自动通知。
- 没有一条被"更早有完整说明"豁免。
- 参考信息：10 条里有 5 条在同一票货**之后**出现了 Delta 相同、写了文字的版本（规则只看更早的，所以不影响判定），说明缺说明的争议后来确实被补上了说明。
- 合成用例：没有更早记录 → 打回；更早有同 Delta 的说明 → 不打回、转人工；同 Delta 的说明在**之后** → 仍打回。
- 预判用到的第 5.5 步历史诊断（预判模式）计数也列在 summary 里，与 02 §7.2 一致。

## 局限
- "打回是否正确"的精确率（02 §9.2，目标 100%）需要审核员确认，现在只有规则层面的检验。
- PPG 是否愿意自动退回、用什么渠道和模板，还没有确认（02 §10.2-12）。
- `REC.TEXT.NO_NUMBER`（有费用名没金额）是否也自动打回，是待定的设计选择（02 §10.1-8），现在不打回。
- 通知文字是诊断目录里的中文草稿，还没有给承运商用的英文版。
