# T17 正文：落实已定的修改，冻结规则

日期：2026-11-15。分支 `leg6-fixes`，冻结标签 `t17-frozen`。没有调模型，花费 0；没有改 SKILL.md、代码表内容、mock、标注原件；第四轮 mock 没有读（这一轮做的过程中它没有出现）。读法来自开发集全量 `devFullV12-5d09`、mock 第三轮 `mockR3V12-f0d3`，第 3 节另用 `devFull-4823`。脚本 `scratch/eval/t17_recompute.py`、`t17_placeholder_54.py`、`scratch/annotation/t17_corrections.py`；逐条结果在 git 忽略的 `data/interim/eval/t17/`。证据级别：人工标注是人工审核；mock 第三轮是样本内（这些修改就是看着它设计的）。

## 1. 结论

1. **四项修改落实了，第五项按事先定的条件没有实施。** 规则升到 v1.3。开发集全量上，四项合起来只多送人工 6 条说明（6 票货），全部来自“以点开头的小数被计入”。
2. **mock 第三轮上 Recall 明显上升，Precision 没降。** 按 mock 答案：Recall 85.2% → 91.7%，FOR 20.4% → 12.6%，没有新增 FP。按我们的标准：Recall 90.0% → 94.7%，FOR 18.8% → 10.9%。这是样本内结果：修改就是看着这批数据设计的，要等第四轮 mock 验证。
3. **人工标注（按代码表纠正后）：Recall 87.9% → 93.9%，FOR 6.9% → 3.6%。** 剩下 2 条 FN，是按决定恢复原答案的两条：标注人的类别是“燃油”，而代码表把这种写法归到费率更正（待决 P-43）。按代码表也纠正这两条的话，FN 是 0。
4. **三套数据都还没达到 Recall ≥ 95%、FOR ≤ 2% 的目标。** mock 上剩下的 FN 几乎全是改写过的注入词：公开资料里的词表接不住 mock 的拼法，我没有为了它扩词表。
5. **脱敏占位符那 54 条：两次全量运行的金额、计入与否、费用类别完全一样**，没有看到脱敏改变读法的迹象。

## 3. BALANCE DUE 写在最前面

开发集全量有 115 条说明把 BALANCE DUE 写在最前面：6 条是“金额 + 税 = 合计”且算得通，109 条不是；不是的里面 84 条现在被放行，超过任务书定的 30 条，所以这一项**没有实施**。这 84 条里 80 条只有一个 `$` 金额（其中 39 条是燃油档位更正那种写法，如 `TL FSC SHOULD APPLY. BALANCE DUE IS $X`），4 条没有 `$` 金额；文字本身大多清楚，送人工的价值不大。决定 A5 的文字已在 `rules.yaml` 写清楚：写在其他 `$` 金额之后的 BALANCE DUE 才按倍数取代或送人工；写在最前面、“金额 + 税 = 合计”算得通的不送人工；写在最前面的其他写法按决定应送人工，但因上面的数字没有实施。数量乘单价的规则文字也写明了：数量为 1 时没有歧义，不触发。

## 5. 脱敏占位符那 54 条

开发集里被放行、金额附近有脱敏占位符的 54 条说明，在两次全量运行（旧脱敏、提示词 v1.1；白名单脱敏、v1.2）里，金额、计入与否、费用类别 **0 条有差异**。只有 2 条两次的脱敏后文字不同，读法仍然一样。所以这 54 条里没有看到脱敏改变读法的迹象；因为没有差异，也谈不上“脱敏造成”还是“版本造成”。局限：两次运行都做了脱敏，看不到“不脱敏时模型会怎么读”。
