## 1. 声称的结论

1. 主线用真实模型（`claude-sonnet-5-5`）跑完了开发集全量 953 条：每条都经过模型，每条都有运行结果，没有静默失败。全量是在 SKILL.md v1.1 加旧脱敏方式下跑的，没有用最终版本重跑（待决 P-23）。这是任务 03 写在 B04 卡片上的浅绿条件，B04 据此升为浅绿。
2. 本段的规则改动（退回只留两种、依据词表）、SKILL.md 从 v1.1 调到 v1.2、默认脱敏方式改为白名单反转，都按事先写定的规则决定，前后数字见第 5 节。
3. 本段新做的交付物（审核界面、标注包、指标脚本、skill 文件夹）各有测试；其中三项有开发集或公开 mock 上的运行证据。
4. 这些都**不是**深绿的声称：证据全部是样本内的，没有人工审核，深绿的门槛也没有写定。

## 2. 为什么是这个证据级别

开发集全量、样本 A、B2 都来自开发集，写 SKILL.md、规则和依据词表时看过开发集的写法；调优只看 A，在 B2 和公开 mock 上验证，但公开 mock 在确定性核对和两段调优里都用过。审核界面、标注包、指标脚本只在开发集和公开 mock 上跑过。所以全部算“样本内”。预留 mock 和测试集本段没有读。

## 3. 检验方法

- pytest：160 个通过，2 个默认跳过（读测试集编号列的两个）。
- 开发集全量真实模型运行一次，按运行库和留存记录数各类结果。
- 用留存的模型输出重算颜色，量每项规则改动前后的变化（`scratch/autorun/recolor.py`）。
- 公开 mock 同一版本跑三遍量波动；调优两轮，“变差”的门槛在跑之前写进 `docs/autorun/tuning_log.zh.md`。
- 审核界面：19 个测试（合成数据）；另在开发集全量的运行库上以只读方式启动，查接口返回的汇总数，并确认写入被拒绝、库文件没有变化。
- 标注包：14 个测试；在开发集上生成三个包并出生成报告。
- 指标脚本：在调优第 2 轮的公开 mock 运行上跑 `mock` 子命令，和调优记录里的数字对照。
- skill 文件夹：10 个测试校验合成例子。
