# T10 人名脱敏：四个变体的对比（任务 10 第 4 节，第 1、2 步）

主机：MacBook-Pro-130.local。日期：2026-11-10。只做了第 1、2 步，没有调用任何模型接口；第 3 步（对解析的影响）留给 orchestrator。

## 结论

1. **四个变体都通过两条确定性门槛**（开发集 953 条：脱敏改动数字 0 条，费用词或数字被遮 0 条）。
2. **按漏检率排序**（1000 条已知答案的合成句）：白名单反转 `allowlist` 10.9% ≈ 本地模型 `local_ner` 11.0% < 人名表 `names_list` 16.8% < 现状 `presidio` 29.0%。前两名只差 1 条，在抽样误差内（109/1000 的 95% 区间约 9.0% 到 12.8%），不能分出先后。
3. **两者的漏检互补**：`allowlist` 的漏检几乎全是"既是人名又是常用词"的名字（107/109）；`local_ner` 的漏检分散在罕见名和歧义名。额外测了并集 `allowlist+local_ner`：漏检 4.8%，同样通过两条门槛。它不在任务书的四个变体里，是否进入第 3 步由 orchestrator 定。
4. **现状的两个问题**（只在合成句上暴露，开发集上是 0）：68 条合成句里有费用词被遮，1 条改动了数字。原因是现有上下文规则"`FROM/OF PPG` 前面两个词都算人名"，名字只有一个词时把前面的费用词一起遮掉。默认行为必须保持不变，所以没有改这条规则；三个新变体在出口处统一裁掉费用词和数字，这个问题不存在。
5. **没解决的**：没有任何上下文、又同时是常用词的单个名字（如句末单独一个既是名字又是普通词的词），所有变体都大量漏掉（最好的并集仍漏 35/166）。

## 测量工具怎么做的

脚本 `scratch/redaction/measure.py`，一条命令复现：`uv run python scratch/redaction/measure.py`。

1. **人名在开发集的真实位置**：以 B01 人工确认过的人名词为准，共 28 处，归并数字后是 5 种句式。现有脱敏器 28 处全部命中；通用提示语模式单独只能找到 2 处。另有 1 处脱敏器命中和 1 处提示语候选不在确认名单里，没有当作人名。句式含真实文本，存在 git 忽略的 `data/interim/redaction/`。
2. **不在开发集里的人名**（写在脚本里，全是合成的）：常见名 30 个、常见姓 31 个、罕见名 34 个、罕见姓 31 个、既是名字又是常用词的名 44 个和姓 29 个（原列 30 个，1 个在开发集出现过，已剔除）。逐词核对过，没有一个在开发集文本里出现。罕见名姓 65 个里有 29 个在人名表中，36 个不在。
3. **造句**：四组，共 1000 条。
   - 真实位置 300 条：把名字填进 5 种真实句式，每种句式权重相同。
   - 规则认识的提示语 300 条：15 个通用子句（如 `APPROVED BY {NAME}`），接在不含人名的开发集句子的句末、句首或句中。这一组对写了对应规则的变体是样本内。
   - 规则里没有的提示语 250 条：12 个通用子句，写在测量之前，之后没有把它们加进任何规则。
   - 无提示语 150 条：名字单独放在句末或句首（开发集里确有一处这样的真实位置）。
   - 每组里六类名字均分：常见、罕见、歧义，各分单名和"名 + 姓"。
4. **漏检**：名字的任何一个字母没被遮住就算漏。**误遮**：遮盖范围里（名字本身除外）出现费用词表里的词或数字。费用词表取自 `config/taxonomy.yaml` 的定义和写法，共 181 个词。

## 四个变体

选择方式：环境变量 `FL_REDACTION_ENGINE=<名字>`（只影响这一次运行），或改 `config/rules.yaml` 的 `redaction.engine`。不设就是 `presidio`。写错名字会报错，不会悄悄变成不脱敏。代码在 `src/freight_lineitems/redaction_variants.py`，`textprep.person_spans` 里只加了分发。邮箱、电话的处理和 `[PERSON_n]` 格式四个变体相同。

| 名字 | 做法 |
|---|---|
| `presidio` | 现状：按词典转大小写后用 Presidio 找 PERSON，加现有上下文规则。已核对：开发集和公开 mock 共 1328 条文本，输出与改动前逐条相同。 |
| `names_list` | 人口普查人名表（5163 个名、3 万个姓）。只是人名的词，出现就遮，并带上紧邻的姓或名。同时是常用词的名字（表里标了 2262 个）只在人名语境里遮：通用提示语之后、`FROM/OF PPG` 或"批准、确认"类动词之前、紧邻一个只是人名的词。`BILL OF LADING`、`WILL CALL` 这类接续不遮。 |
| `allowlist` | 在 `names_list` 之上，凡是不在放行表里的字母词都遮。放行：数字和带数字的编号、费用词表、单位和日历词、州省代码、一份通用货运缩写表（`rules.yaml` 的 `allow_words`）、常用英文词（SCOWL 35 级及以下，约 4 万词）、与费用词只差一次编辑的拼写。一两个字母的词不遮。 |
| `local_ner` | GLiNER small v2.1（零样本实体模型，标签 `person`），用 onnxruntime 在本机 CPU 上跑，输入是原样的大写文本，加现有上下文规则。没有引入 torch：输入输出按 gliner 库的格式自己拼，和 gliner 库逐条核对过，250 条里 250 条遮的词相同。 |

三个新变体出口处统一做一次裁剪：只保留独立的字母词，去掉费用词和其他受保护的词。所以遮盖范围里不会有数字、和数字连写的编号、费用词表里的词，这是构造保证的，不依赖数据。

## 局限

- **样本内的部分**：真实位置只有 28 处、5 种句式，现有上下文规则就是照着它们写的；"规则认识的提示语"一组和 `names_list` 的规则出自同一人。相对独立的是"规则里没有的提示语"和"无提示语"两组，以及 13.1 万个表外姓氏的放行率。
- **开发集误遮为 0 是样本内结果**。`allowlist` 在开发集只多遮 3 个非人名词，是因为开发集用词很规整；`allow_words` 表里有四个词（`DETN`、`PYMT`、`REPOSITIONING`、`OVERPAYMENT`）是先在开发集上看到被遮、再确认属于通用货运用语后加入的；没有这份表时开发集会遮 9 个非人名词（其中 3 个是 `DETN`），而不是 3 个。新承运商的生僻缩写会被 `allowlist` 遮掉，费用词表保护不到它们，这要靠第 3 步和以后的数据看。
- **合成名字是手写的**，罕见名偏长、偏外语，和常用词只差一个字母的短名字少，所以另用人口普查表外姓氏量了这一类。
- **歧义名**在没有上下文时无解：`BILL`、`MAY` 这类词在货运文本里绝大多数时候不是人名，遮掉会伤到解析。
- `local_ner` 每 1000 条约 6 秒，比其他变体慢两个数量级，但相对模型调用仍可忽略。
- 运行时能发现"脱敏改动数字"，发现不了"漏掉人名"，这一点没有变。

## 选择（按事先定的规则）

- 三条都满足的：`names_list`（漏检 16.8%）、`allowlist`（漏检 10.9%）。取漏检率最低的 **`allowlist`（白名单反转）作为默认**，`rules.yaml → redaction.engine` 已改。
- `allowlist+local_ner` 的漏检率最低（4.8%），但解析这一条没过，不选。
- 所有变体里，没有上下文的单个“既是人名又是常用词”的名字（BILL、MARK）仍然大量漏检；`allowlist` 在这一类上漏 107/332。

## 改成默认之后发现的两件事

1. **白名单会遮住词表里没有的费用词。** 开发集上费用词误遮为 0（门槛按开发集算，满足），但合成文本里 `PER DIEM` 的 `DIEM`、`TARP` 被遮住了。已在 `redaction.allow_words` 里补了一批通用货运用词（约 120 个，不取自数据）。补完之后开发集 953 条的脱敏结果逐字不变（所以上表的 A、B2 运行仍然有效），公开 mock 有 5 行变了（`DRAY`、`TARP` 不再被遮）。1000 个测试句上各变体的漏检数不变。这是白名单方式固有的风险：没见过的费用词会被遮成 `[PERSON_n]`，模型读不到费用名，记录会带“有金额无费用名”送人工，不是静默错误，但会多占人工。列入待决 P-20。
2. **白名单让模型报告注入的次数变少。** 公开 mock 的 30 个注入事件里，模型报告的从 25 到 27 个降到 18 个，代码加模型合计标出 22 个（原来 25 个）。原因是注入文字里的非常用词被遮住，模型看到的是占位符。主张金额没有受影响（注入事件读对 29/30，和原来一样）。事先定的选择规则没有包含这一项，所以仍按规则选 `allowlist`，问题列入待决 P-20，备选是退回 `names_list`。

公开 mock 上最终版本（v1.2 加 `allowlist`，`finalMock-1ba4`）：主张金额正确 333/360（基线三遍 327 到 330），三种建议 146 / 224 / 5。

跑的时候注意：
- 用 `FL_REDACTION_ENGINE=<名字>` 选变体；这个环境变量目前不会写进运行记录的版本信息，需要在运行说明里另记。
- 换变体后发给模型的文本会变，之前的模型输出不能复用。

按事先定的规则，默认值的选择要等这一节填完：改动数字为 0、开发集费用词误遮为 0（四个变体都满足）、解析结果不差于波动范围，三条都满足的变体里取漏检率最低的。
