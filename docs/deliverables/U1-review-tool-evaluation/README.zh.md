# U1 开源审核工具评估

日期：2026-11-10。对应工作量表 v2 第 3.8 节 U1、决定 1.8。

## 结论

**自建最小可用版（工作量表第 4 节的"最小可用版"），不用 Label Studio 或 Argilla。** 自建版只用 Python 标准库，已在 U2 完成，见 `docs/deliverables/U2-review-ui/README.zh.md`。

三条理由：

1. **发票一层做不出来。** 决定 6.1、6.2 要求按发票列出、按严重程度计数、点开看发票总览。Label Studio 和 Argilla 都以"一条记录一个任务"为单位，任务是平铺的，没有"几笔争议归到一张发票下面并汇总计数"这一层。这正是工作量表第 4 节替代 A 写明"做不到"的三项，而这三项占了 U2 完成标准的一半。
2. **决定的记录方式对不上。** 我们的 `reviewer_decision` 表（`config/schema_v1.yaml`）要求只追加、保留全部历史、清除标识时必须指向具体哪一条标识并填理由。Label Studio 开源版没有标注历史（官方对比页列为付费版功能），条件必填也要靠付费版的插件；两个工具的结果都存在各自的库里，还要另写导入导出脚本来回同步。
3. **自建的成本很低。** 界面只读我们已有的 SQLite 库、只写一张表，标准库就够，不新增依赖，不联网，数据不离开本机。

按项目负责人的规则（现成工具满足大部分需求就用，否则自建最小版）：现成工具在下表 16 条里完全满足的各只有 1 条，另有 7 条只能做到一部分，不算"满足大部分"。

**评估方式的限制**：本次根据官方文档和代码仓库页面评估，**没有安装试用**。表里标"文档"的格子是根据文档判断的，没有实际操作验证。如果以后要重新考虑用现成工具，应先装上试一遍这些格子。

## 各工具的许可证与本地运行

| 工具 | 许可证 | 能否完全在本机运行 | 备注 |
|---|---|---|---|
| Label Studio（开源版） | Apache-2.0 | 能。`pip` 或 Docker 安装，默认 SQLite，本机 8080 端口 | 审核员角色、标注历史、评论、JavaScript 插件、活动日志都只在付费版。是否有遥测本次没有查证，采用前要确认并关闭 |
| Argilla | Apache-2.0 | 能，但要用 Docker 起服务端和 Elasticsearch | 仓库声明进入维护模式：原作者已离开，不再加新功能，只修问题 |
| doccano | MIT | 能 | 面向文本分类和序列标注，没有详查；同样是一条文本一个任务，没有发票一层 |
| Langfuse、Opik、MLflow 的审核队列 | MIT / Apache-2.0 / Apache-2.0 | 可自托管 | 面向模型调用轨迹的评估，不是业务记录的审核界面；只在搜索结果里看到，没有详查 |
| Streamlit（自建用的框架，不是现成工具） | Apache-2.0 | 能 | 工作量表第 4 节举的例子。没有采用：要新增依赖，默认带使用统计（需要在配置里关掉），而我们要的页面标准库就能做 |

## 三个版本的选择（工作量表第 4 节）

| 版本 | 结论 | 原因 |
|---|---|---|
| 最小可用版（自建） | **采用** | U2 完成标准全部做到 |
| 替代 A：开源工具配置 | 不采用 | 按发票总览、按严重程度计数、发票一层都做不到；还要写同步脚本 |
| 替代 B：静态页面加 Excel | 不采用 | 决定要人工导回，容易出错；已有的只读结果页（`scratch/autorun/build_results_page.py`）继续保留作验收用 |
