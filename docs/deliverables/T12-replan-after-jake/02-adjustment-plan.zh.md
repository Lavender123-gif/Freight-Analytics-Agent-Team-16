# T12 调整计划：因为新信息，哪些东西要变

日期：2026-11-13。本文只写方案，本轮没有改任何代码、规则、SKILL.md、测试、cards.yaml 或 mock。数字出处见 `01-stocktake.zh.md`，下面用“摸底第 N 节”指代。

来源标记：**A** = 你已定；**B** = 来自 Jake 的回复；**C** = Claude 的建议，附我的意见；**D** = 待批准，不排进必做。

## 结论

1. **改动量比看上去小。** 撤掉 Delta 在开发集全量上只改变 11 条记录的颜色（摸底 4.5）；承运商发票和票货本来就一一对应，现有的“发票”一层就是票货一层（摸底第 5 节）；用留存读法做最简单的汇总，Jake 的两个例子已经精确复现。
2. **真正新增的只有一个部件：票货汇总层。** 它由代码按费用代码判定说明之间的关系，不需要模型判断，不增加模型调用。
3. **C 组八条里，五条我同意，三条有不同意见**：C3 在仓库里已经是现状，不需要做；C6 的“上调权重”在三档制下没有对应物，而且降级“提到税”必须同时升级“写了税没写税额”；C7 的两个例子在开发集里、开发时见过，只能当合理性检查。
4. **有两个设计点第 1 节没有覆盖，不处理会算错 Jake 的例 1**：取代规则必须把税排除在外；两条说明 Event Date 相同时要有确定的先后规则。
5. **撤掉 Delta 之后，系统对“读得对不对”不再有任何独立的数字参照。** 解析通过的比例会上升（760 到 766 或 778），但这不是质量变好的证据。人工标注的评估要先于任何质量结论。

## 4. 票货汇总层的设计

### 4.1 数据结构

**说明**（合并后的单位，一次模型调用）：

- 键：SHIPMENT_GID、Event Date、规范化后的文字。
- 字段：原始行号列表、PK 列表、订单数、是否含 PK 相同或为空的副本、该条的读法和颜色。

**票货汇总**（每次运行每票货一份）：

| 字段 | 内容 |
|---|---|
| 票货键 | SHIPMENT_GID。SAP BOL 作为显示字段（开发集有 6 行 SAP BOL 为空，SHIPMENT_GID 没有空值，两者一一对应） |
| 原始金额 | Shipment Amount（开发集上同一票货没有不一致） |
| 费用行 | 每行：费用代码、原文费用名、金额、是否税、来自哪条说明、状态（计入 / 被哪一行取代 / 不计入） |
| 默认变化额 | 状态为“计入”的各行之和 |
| 新总额 | 原始金额加默认变化额 |
| 另一种读法 | 每个“可能重复”标识各带一个改判后的总额；另给全部改判组合里的最小值和最大值 |
| 完整性 | 完整，或“有 N 条说明没有可用读法” |
| 标识和颜色 | 见 4.5 |

同一费用代码的多行不合并显示：Jake 的例 1 里税就是分两行列的。

### 4.2 合并副本的规则

1. 键相同的行合并成一条说明，只调一次模型。
2. 这些行的 PK 各不相同：正常结构，记订单数，不打标识。
3. 这些行里有 PK 相同或 PK 为空的：打重复标识（提示级别还是送人工，见 4.5）。
4. 文字相同但 Event Date 不同：不是副本，是两条说明，进入 4.3。

### 4.3 多条说明之间的关系怎么判定

三种做法：

| 做法 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| **甲（推荐）** | 代码按费用代码判定 | 确定、可重复、不花钱、能解释；符合决定 4.2 | 依赖模型给每条说明标的代码准确；“其他”和没有费用名的金额判不了 |
| 乙 | 把同一票货的前几条说明一起给模型，让它判断 | 能处理代码判不了的情况 | 违反决定 4.2；多一次调用；自报类判断在重复运行里不稳定（第一段 57%）；难以测试 |
| 丙 | 甲为主，甲判不了的交给模型 | 覆盖面最大 | 两套逻辑，工作量最大 |

**推荐甲，判不了的一律送人工并给出默认数。** 规则按顺序：

1. **排序**：按 Event Date，相同时按原始行号。开发集有 10 票货存在 Event Date 相同的不同说明，包括 Jake 的例 1。
2. **同一项费用，后一条取代前一条（A3）**：后一条说明里某个非税费用代码，如果在更早的、仍然计入的行里出现过，更早的那些行改为“被取代”。
3. **税跟着它所在的说明走**：税代码不参与第 2 步的比较。一条说明的非税行全部被取代时，它的税行一起被取代；只被取代一部分时，税行保留，并打标识送人工（分不清税属于哪一项）。不这样做，例 1 会少算一行税。
4. **不同的费用，相加（A3）**。
5. **相同金额（A4）**：后一条的某个金额与更早某行的金额相同、但代码不同：默认相加，打“可能重复”标识，另一种读法是只算一次。
6. **1.03 到 1.07 倍（A5）**，阈值写在 `rules.yaml`：
   - 同一条说明里，BALANCE DUE 后面的金额约等于前面某个金额的 1.03 到 1.07 倍：只计 BALANCE DUE 那个数，前面那个不计。
   - 相邻两条说明各只有一个金额、后者是前者的 1.03 到 1.07 倍：后者取代前者，即使代码不同或后者没有费用名。
   - 其余的 BALANCE DUE 写法：默认数取模型的读法，打标识送人工。
7. **判不了的**：某一方是“其他”代码且原文费用名不同、没有费用名、一个金额对多个代码。默认相加，打标识送人工。
8. **有说明没有可用读法**：默认数取其余说明之和，票货标为不完整，送人工。

第 6 条的第一种情况有两个实现选项：

| 选项 | 内容 |
|---|---|
| **推荐** | 代码识别这个数字形态并决定默认总额；模型的读法照常保留。两者不同时打标识。理由：这是纯数字规则，代码做得确定、可测 |
| 备选 | 在 SKILL.md 里写成约定让模型照做，代码只核对。缺点：又是一次提示词改动，而且同一条规则靠模型执行会有波动 |

### 4.4 默认总额和另一种读法的总额

- 默认总额只由 4.3 的规则算出，任何情况下都有一个数（A4）。
- 每个“可能重复”标识带三样：涉及哪两行、默认怎么判的、改判后的总额。
- 一票货有多个这类标识时，另给“全部改判组合里的最小总额和最大总额”，不逐一列组合。
