## 7. 局限

- 0 漏检是样本内结果，真实漏检率要在没见过的数据上测。
- 人名识别把 3 个不是人名的词当成人名替换掉了，涉及开发集 5 条记录（5 行，各为单独的事件）：
  - `DELV`，3 条，出现在 "SPECIAL DELV. CHG" 里，是 delivery 的缩写，整句指特殊送货费；
  - `TONU`，1 条，Truck Ordered Not Used，指派了车但没用上而收的费用；
  - `ENTERD`，1 条，是 ENTERED 的拼写错误，原句 "WAHT YOU HAVE ENTERD CORRECT AS BILLED"。

  正式运行时 LLM 只看到脱敏后的文字，前两个词被替换后，费用名称就丢了（变成 "SPECIAL [PERSON]. CHG"、"-250 [PERSON] NOT NEED"），模型没法把这笔金额归到正确的费用类型。`ENTERD` 本身不是费用名，丢的是"计费正确"这层意思。

  第 6 节"误删 2 个词"漏算了 `DELV`：`presidio_eval.py` 按 `[A-Z][A-Z'.-]*` 切词，切出来的是带句点的 `DELV.`，比识别出的范围 `DELV` 多一个字符，所以被判为没有覆盖。

  这一条是 2026-11-03 为外部测试数据导出逐条核对时发现的。导出脚本 `scratch/deliverables/E1_mock_gen_export.py` 用白名单保留了这 3 个词，原型代码没有改。
- 注入规则只覆盖少数指令式句式，没有经过对抗样本检验（02 §9.4 E5）。
- 运行时能发现"脱敏误删数字"，发现不了"漏掉人名"。

## 9. 升到深绿的检验方案

- **独立数据**：合成注入数据。用开发集里从未出现过的人名和邮箱，按开发集里人名、邮箱常出现的位置（位置分布从开发集统计，不抄真实人名）插入开发集文本。插入的位置和内容已知，相当于有标准答案。另外建一个注入对抗样本集，与 V3 的 E5 共用。两者都不用测试集。
- **做法**：对合成文本运行门控，统计人名、邮箱漏检率，脱敏后数字字符是否被改动，以及误删的费用词；对抗样本集统计注入检出率和正常请求的误报率。
- **门槛**：人名漏检率 ≤ 2%；脱敏动了数字 0 次；对抗样本检出率的门槛在建样本集时另定 `[建议，待确认]`。门槛要在生成合成数据、跑检验之前写进卡片的完成标准。
- **是否依赖 B04**：不依赖。门控在调用模型之前，现在就能做。
