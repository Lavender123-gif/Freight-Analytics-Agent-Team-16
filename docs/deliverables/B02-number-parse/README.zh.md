# B02 第 2 步：数字识别

## 这一块做什么
在脱敏文本里把每个数字找全、按顺序编号（`#1`、`#2`……），先认领日期时间（`D1`……），记下每个数字的客观特征：原文写法、标准化值、是否带 `$`、是否由空格分隔的数字组合并而来、前导点、减号、前后词、单位词。**覆盖检查**保证文本里每个数字字符都被某个数字、日期或"未识别区域"（`?1`）认领，没有数字会被静默漏掉。模型之后只能引用这些编号，不能自己写金额。

## 输入和输出
- 输入：B01 输出的脱敏文本
- 输出：数字表、日期表、未识别区域、标记文本（给模型看的版本），以及第 2 步的诊断
- 代码：`scratch/prototype/number_parse.py`、`checks.py` 的 `step2_diagnostics`（原型，未改动）

## 一条命令复现
```
sh scratch/deliverables/run.sh B02_number_parse.py
```
结果写到 `results/summary.md`、`results/examples.md`；每种文本的完整解析在 git 忽略的 `data/interim/deliverables/B02/`。

## 检验数据
开发集全量：908 条事件，529 种不同的脱敏文本（含空文本）。不是测试集。数字与 02 §7.2 对照。

## 结果
- 529 种文本 **全部通过覆盖检查**（与 02 §7.2 一致）。
- 共识别 809 个数字、127 个日期时间、1 个未识别区域（`CV19`）。
- 第 2 步 8 种诊断的事件数与 02 §7.2 **全部一致**：空格合并 99、前导点 7、紧贴减号 2、小数位异常 1、未识别区域 1、只有数字 6、没有数字 1、文本日期晚于 Event Date 6。
- 例子 5 条（处理前的文本 → 标记文本和数字表）见 `results/examples.md`：空格分隔的金额、前导点、未识别区域、日期 + 天数 + 单价、紧贴减号。

## 局限
- 覆盖检查只保证"没有漏"，不保证"切对了"：空格合并（`$ 8 400.00` → 8400.00）是规则推断，可能本应是两个数。切分正确率要靠标注集测（02 §9.2，V1）。
- 99 处空格合并里 94 处是重量，5 处是金额（02 §7.2）；金额被合并后计入主张时，第 4-5 步会另加诊断。
- 例子中的 `-250 [PERSON]` 是 B01 把 `TONU` 误删成人名的结果，不是本步的问题。
- 规则来自开发集上的写法；未见承运商的新写法会落到"未识别区域"，由模型解读并逐位比对。
