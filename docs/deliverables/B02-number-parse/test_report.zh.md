## 1. 声称的结论

开发集 529 种不同的脱敏文本里，每个数字字符都被某个数字、日期或未识别区域认领（覆盖检查全过）；第 2 步 8 种诊断的计数与 02 §7.2 一致。

## 2. 为什么是这个证据级别

解析规则（空格合并、前导点、日期认领等）来自开发集上的写法，检验也在同一开发集上做。属"样本内"。切分是否正确没有人工核对。

## 3. 检验方法

- 用原型 `number_parse.py` 解析每种文本，运行覆盖检查（每个数字字符必须被认领）。
- 统计数字特征（`$`、前导点、紧贴减号、空格合并、结尾点、单位词）。
- 用 `checks.py` 的 `step2_diagnostics` 统计第 2 步 8 种诊断的事件数，与 02 §7.2 对照。

## 4. 检验数据

开发集全量：908 条事件，529 种不同的脱敏文本（含空文本）。**不是测试集**；没有读原始 Excel。

## 5. 门槛及是否事先设定

- 覆盖 100%：这是设计上的不变量（02 §3：没认领的数字字符成为未识别区域），但**没有事先写成本卡的门槛**。
- 诊断计数：期望值是 02 §7.2 的数字，属复现目标。
- 切分正确率：**门槛未事先设定**，也没有测（02 §9.2 只定了指标）。

## 6. 结果

- 529 / 529 通过覆盖检查。
- 共识别 809 个数字、127 个日期时间、1 个未识别区域。
- 数字特征（按文本计）：带 `$` 684、空格合并 62、单位词 81、前导点 5、结尾点 5、紧贴减号 2。
- 第 2 步诊断（事件数），与 02 §7.2 全部一致：空格合并 99、前导点 7、紧贴减号 2、小数位异常 1、未识别区域 1、只有数字 6、没有数字 1、文本日期晚于 Event Date 6。

## 7. 局限

- 覆盖检查只保证"没有漏"，不保证"切对了"：空格合并（例如 `$ 8 400.00` → 8400.00）是规则推断，可能本应是两个数。
- 99 处空格合并里 94 处是重量，5 处是金额（02 §7.2）。
- 例子里的 `-250 [PERSON]` 是 B01 误删 `TONU` 的结果，不是本步的问题。
- 未见承运商的新写法会落到未识别区域，由模型解读并逐位比对。

## 9. 升到深绿的检验方案

- **独立数据**：(a) 合成数字写法集：按已知答案生成文本，包括开发集里少见或没有的写法，例如千分位逗号、`USD`、全角符号、多个金额相邻、货币符号在后（哪些在开发集里确实没有，生成前先统计）；(b) V1 完成后，用人工标注的切分做人工审核。
- **做法**：(a) 运行覆盖检查，并把切分结果与已知答案逐个比较；(b) 在 V1 标注集上算每个数字的切分正确率，按写法分层（02 §9.2）。
- **门槛**：覆盖 100%；切分正确率 ≥ 98% `[建议，待确认]`。门槛要在生成合成数据、开始标注之前写进卡片的完成标准。
