# U2 审核界面最小可用版

日期：2026-11-10。对应工作量表 v2 第 3.8 节 U2、决定第 6 节。为什么自建，见 `docs/deliverables/U1-review-tool-evaluation/README.zh.md`。

## 结论

U2 完成标准的四项都已做到，并在真实运行（样本 A，100 笔争议、80 张发票）上实际启动验证过。界面只用 Python 标准库，没有新增依赖，只在本机 127.0.0.1 上提供，只显示脱敏后的文字。

界面不对"该不该付"给出任何建议。颜色和标识是运行时由规则算好的；按钮只把审核员本人的决定追加到 `reviewer_decision` 表，不改 OTM，不发送任何东西。

## 怎么启动

```
uv run python -m freight_lineitems.review_ui --run <run_id>
```

然后在浏览器打开终端里打印的地址（默认 `http://127.0.0.1:8765/`），Ctrl-C 停止。

| 参数 | 作用 |
|---|---|
| `--run <run_id>` | 打开 `data/interim/runs/<run_id>/run.sqlite` |
| `--db <路径>` | 改用指定的库文件（例如一份副本）；库里只有一次运行时可以不写 `--run` |
| `--reviewer <编号>` | 写进每条决定的审核员内部编号，默认 `reviewer-1`。只能是字母、数字、`-`、`_`，不要用姓名或邮箱 |
| `--port <端口>` | 默认 8765 |
| `--read-only` | 只读打开，页面不出现按钮，库文件不会有任何改动 |

注意：不加 `--read-only` 时，决定直接写进该次运行的库文件，而且**写了就删不掉**（表只追加）。只是想看看、试一试时，用 `--read-only`，或者先把库复制一份再用 `--db` 打开副本。

文件：

- `src/freight_lineitems/review_ui.py`：读库、记录决定、本机网页服务
- `src/freight_lineitems/review_ui.html`：页面（样式和脚本都在这一个文件里，不引用任何外部资源）
- `tests/test_review_ui.py`：测试（合成数据）

## 决定的四个选项和记录方式

选项来自决定 6.4，取值从 `config/schema_v1.yaml` 的 `reviewer_decision.action` 读出，代码里不另写一份：

| 界面上的按钮 | 存入的值 | 规则 |
|---|---|---|
| 认可这份读法（任务 20 前叫“批准”，P-24 改名） | `ACCEPT_READING` | 理由可不填；记录的是认可读法，不是批准付款 |
| 退回承运商 | `RETURN_TO_CARRIER` | 理由可不填；系统不发送任何东西 |
| 清除标识 | `CLEAR_FLAG` | 必须指明是这笔争议的哪一条标识，必须填理由 |
| 暂缓 | `HOLD` | 理由可不填 |

这四个值是审核员自己操作的记录，不是系统的建议。OTM 里实际有哪几种操作仍待 Jake 回答（J10），回答后可能要改。

- 表结构用 schema 里已定义的 `reviewer_decision`，没有另建表。本版写入的列：编号、争议、标识（仅清除时）、动作、理由、审核员编号、时间（UTC）。其余列（批量操作编号、改过的草稿、对标识的评价、读数更正）本版留空。
- 只追加：界面打开库时给这张表加了两个触发器，禁止修改和删除。改主意就再点一次，新旧两条都在，最新的一条"批准 / 退回 / 暂缓"算当前决定。
- 清除标识不算对这笔争议做了决定。被清除的标识在页面上划掉并标"已清除"；发票列表里按规则算出的计数不变，另外显示"已清除标识 N"。
- 记录决定不改动库里其他任何表，下游导出（`export_facts`）不受影响。"审核员清理之后再汇总"（决定 5.4）本版没有做。
- 不在取值表里的动作（例如 `PAY`、`DENY`）一律拒绝，不写库。

## 故意没有包括的（U4 和其他）

- 批量清除、发票一层的批量操作（U4）
- 之前批次的上下文（U4）
- 距离（U4）
- 退回草稿的编辑（U4）；本版只读显示规则生成的草稿
- 核实提示（U4）
- 在原文里高亮每个数字的位置
- 对标识的评价（有用 / 噪音 / 错）和读数更正：表里有列，界面没有做
- 登录和多人同时使用：审核员编号由启动参数给出，没有身份验证。只适合一个人在自己的机器上用
- 标识只显示代码和证据，没有中文解释（规则的大白话说明是 R2）
- 英文界面
- U3 走查还没有做

## 数据安全

- 只绑定 127.0.0.1；请求头里的主机名不是本机时拒绝；记录决定的请求必须是 JSON 格式，别的网页无法代替审核员提交。
- 只读 `dispute.description_redacted`，不读原始行（`source_row`）和发给模型的输入。
- 页面不引用任何外部资源，并用内容安全策略禁止向外连接；承运商的文字一律按纯文本显示。
- 承运商、票货、发票号会显示在本机页面上（审核员需要）。行级数据不写进任何受版本管理的文件；截图在 `data/interim/review_ui/`（不入库）。
- 审核员填的理由是自由文字，会原样存进库里。请不要在理由里写姓名或邮箱。
