# A2 问题盘点（01、01b）：数字复现

> `copies/` 下是 `docs/analysis/01_problem_inventory.md`、`01b_version_pairs.md` 的副本（任务 03 复制，方便单独展示）。**以 `docs/analysis/` 下的原件为准**；原件修订后需重新复制。

中文版为准；英文版见 `README.en.md`。

## 这一块做什么

检验两份问题盘点报告 `docs/analysis/01_problem_inventory.md` 和 `docs/analysis/01b_version_pairs.md` 里标为【事实】的关键数字，能否由 `scratch/analysis/` 下的脚本原样重跑出来。脚本和报告都没有修改；本卡只是重跑、取数、对照。

## 输入和输出

- 输入：开发集 `data/processed/dev.csv`（由 `scratch/analysis/common.py` 读取）；分析脚本 `a1_structure.py` 到 `a11_r6_p3.py`；两份报告中的数字（写死在复现脚本的对照表里）。
- 输出：
  - `results/comparison.md`：61 项数字的对照表（报告位置、报告值、脚本、重跑值、是否一致、说明），只有汇总数字。
  - `results/examples.md`：5 个已脱敏的短示例（问题模式 + 开发集计数）。
  - 各脚本的完整输出保存在 git-ignored 的 `data/interim/deliverables/A2/<脚本>.txt`（可能含行级文本，不入库）。

## 一条命令复现

在仓库根目录执行：

```
uv run python scratch/deliverables/A2_reproduce_inventory.py
```

脚本依次以子进程运行 11 个分析脚本，保存输出，用正则取数，打印并写出对照表。不调用任何 LLM，不需要额外依赖。

## 检验数据

开发集全量：953 行，按 P1 去重后 908 条争议事件，813 个 shipment，18 个承运商。**不是测试集**；没有读取 `data/processed/test.csv` 或原始 Excel。

## 结果

共 61 项（多值项按 “/” 逐项比较，小数四舍五入到 3 位）：**57 项一致，2 项不一致，2 项没有脚本输出、无法复现。**

不一致：

1. **01b §2.4，前一版非 DECLINED 的有序对中“修改版”的数量**：报告 57（85%），重跑 56（84%）。按 a9 的交叉表手算：67 对 − 重复提交 2 对 − 无关新争议 9 对 = 56。报告是笔误，结论（与 DECLINED 组的 78% 没有明显差别）不变。
2. **01 P3，“BALANCE DUE 且有 ≥2 个 `$` 金额”53 行中除 45 行以外的 8 行**：报告写“Delta = 不含余额的各项之和 4 行，其他 4 行”，a4 实际输出的分类是“Delta = 余额（最后一个金额）2 行，其他 6 行”，没有“不含余额”这一类。45 行这个主数字可以复现。01b §3.3 和 §5 第 3、4 条已经修正了 P3：同一写法下 Delta 不含余额的是 5 行（唯一一条 4 行、后续争议 1 行），这个修正值由 a11 复现，一致。

无法复现（没有任何脚本输出这个数）：

1. 01 P11：“同一文本最多出现 75 次”。
2. 01 P12：“非 $20 的行金额在 $20.09 到 $535.18 之间”中的下限 20.09（a6 只输出全部金额的范围 20.00 到 535.18）。

被 01b 修正过的数字，按修正值对照，并同时核对原值：

- 01 P2 的 21.9%（209 行）→ 01b §5.2 修正为 21 行（2.2%），上限 48 行（5.0%）、61 行（6.4%）。修正值和原值都能复现（分别来自 a11 和 a3）；原值的解读已被取代。
- 01 P2 的 41/94 → 01b §5.8 修正为 39 处约 5% 增幅（比值 1.032 / 1.050 / 1.055，29 处落在 1.0475 到 1.0525）。修正值和原值都能复现（a10、a5）。
- 01 P2 的“后续争议 36/95 条 Delta 是数字之和”→ 01b §5.1 说明这是同一文本内的加总，不是跨争议累计；数字本身可复现。
- 01 P3 → 见上文不一致第 2 条。

另有一处单位写法问题，计为一致：01b §0 称最大、第二大、第三大承运商分别有 580、164、87 “行”；这三个数是**事件数**（a8），按行算是 582、185、87（a1）。

## 局限

- 所有计数只在开发集上成立，不代表测试集或全量数据。
- 取数靠正则匹配脚本的打印格式；脚本输出格式一旦改动，复现脚本会显示“（未匹配）”而不是给出错误数字。
- 报告中的数字是从报告正文手工抄进对照表的，只覆盖 61 项关键数字，不是报告里的全部数字；【推测】类内容不在检验范围内。
- 一致只说明“脚本重跑得到同一个数”，不说明脚本里的规则（例如 a4 的正则、a9 的关系标签）本身是对的；报告自己说明这些规则来自通读开发集，对没见过的承运商不保证。
- 01b 中“逐对人工核对 85 对”等人工阅读的结论无法由脚本复现。
