- **卡片颜色**：🟩 浅绿（看板：[A2](../../status/project_status.zh.md#card-a2)）
- **卡片类型**：分析类。"检验"是脚本可复现与数字核对，不是对某个功能的测试。
- **整理日期**：2026-11-03（任务 04）。内容取自任务 03 的交付物，本次没有重跑任何检验。
- 交付物说明：[README.zh.md](README.zh.md)；对照表：[results/comparison.md](results/comparison.md)；示例：[results/examples.md](results/examples.md)；英文版：[test_report.en.md](test_report.en.md)

## 1. 声称的结论

两份问题盘点报告（`docs/analysis/01_problem_inventory.md`、`01b_version_pairs.md`）里标为【事实】的关键数字，能由 `scratch/analysis/` 下的脚本原样重跑出来；不一致之处已经列出，不影响报告的结论。

## 2. 为什么是这个证据级别

复现用的是写 01、01b 时读过的同一个开发集；对照表里的报告值由任务 03 从正文手抄，取数和对照也由同一执行方完成，没有其他人核对。属"样本内"。

## 3. 检验方法

`scratch/deliverables/A2_reproduce_inventory.py` 以子进程依次运行 `a1_structure.py` 到 `a11_r6_p3.py` 这 11 个脚本，用正则从输出里取数，与写死在对照表里的 61 项报告值逐项比较（多值项按"/"逐个比较，小数四舍五入到 3 位）。被 01b 修正过的数字按修正值对照，同时核对原值。

## 4. 检验数据

开发集全量：953 行，按 P1 去重后 908 条事件，813 个 shipment，18 个承运商。**不是测试集**；没有读 `data/processed/test.csv` 或原始 Excel。

## 5. 门槛及是否事先设定

**门槛未事先设定。** 任务 03 没有事先写"多少项一致才算通过"，只是如实列出一致、不一致和无法复现的项。

## 6. 结果

61 项中：**57 项一致，2 项不一致，2 项无脚本输出**。

不一致（都是笔误类，结论不变）：
1. 01b §2.4："修改版"数量报告 57（85%），重跑 56（84%）。
2. 01 P3：53 行中除 45 行以外 8 行的细分与 a4 输出不同；45 本身可复现，01b §3.3、§5 已修正 P3，修正值由 a11 复现一致。

无脚本输出：01 P11"同一文本最多出现 75 次"；01 P12 的下限 $20.09。

单位写法：01b §0 的 580、164、87 是事件数而不是行数，计为一致。

## 7. 局限

- 所有计数只在开发集上成立。
- 取数靠正则匹配脚本的打印格式；格式改动时会显示"（未匹配）"，不会给出错误数字。
- 只覆盖 61 项关键数字，不是报告里的全部数字；【推测】类内容不在检验范围内。
- "一致"只说明脚本重跑得到同一个数，不说明脚本里的规则（例如 a4 的正则、a9 的关系标签）本身是对的。
- 人工阅读得出的结论（例如逐对核对 85 对）无法由脚本复现。

## 8. 复现命令

在仓库根目录执行：

```
uv run python scratch/deliverables/A2_reproduce_inventory.py
```

## 9. 升到深绿的检验方案

- **独立数据或核对人**：由写报告以外的组员核对（人工审核）。
- **做法**：组员从 01、01b 正文随机抽约 20 个【事实】数字（不看对照表），自己运行对应脚本核对；再从 01b 的 85 对里随机抽 5 对，读原文判断关系标签（重复提交、修改版、无关新争议）。
- **门槛**：抽查的数字全部一致，或差异已在对照表里；5 对的关系标签没有异议 `[建议，待确认]`。门槛要在开始核对之前写进卡片的完成标准。
- **是否依赖 B04**：不依赖，现在就能做。
