## 这一块做什么
`docs/analysis/02_design_proposal.md` 是整个系统的成型设计：数据模型、逐步规格、61 种诊断的目录、规则配置、agent 和五个工具、开发集实测、10 条端到端走例、评估方案（标注集、指标、baseline、E1-E9 对照实验）、未决问题。本交付物本身就是这份文档；附带一个一致性核对，证明文档里的配置和数字与原型代码、配置文件和一次全新的开发集运行一致。

## 一页摘要
- **方案**：代码先把文本里的数字找全、编号；LLM 只对编号下判断，唯一出口是 `submit_line_items`；提交工具内部检查，"模型能改的错"退回、"数据本身的问题"只记录；之后代码与同一票货更早的记录比对；所有发现成为诊断，汇总成 flag，由 `rules.yaml` 算出三种处置之一：自动打回、转人工、拆分可信（02 §1.1）。
- **与原流程的 13 处不同（D1-D12，含 D3'）**：例如不设 `dispute_type`（D1）、打回预判在模型之前（D4）、给模型"坚持原读法"的出口（D5）、三种反凑数诊断（D6）、`Dispute Status` 不进记录对象（D7）（02 §1.3）。
- **待定**：11 个设计选择（02 §10.1，由项目负责人定）、12 个要问客户的问题（02 §10.2）。
