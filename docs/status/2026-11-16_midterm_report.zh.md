# 中期汇报（2026-11-16）

CMU Intro to AI 客户项目（第 16 组，客户 PPG），写给课程和客户。英文版：[`docs/reports/midterm_report.md`](../reports/midterm_report.md)。数字和项目总结（[`2026-11-16_project_summary.zh.md`](2026-11-16_project_summary.zh.md)）一致，证据见那里。

## 做了什么

承运商用自由文字解释运费调整，PPG 的审核员现在逐条人工读。系统把每段说明变成结构化明细（费用、金额、税单列），对照原文检查，把同一票货的各条说明汇总成客户格式的表（原始运费、带客户费用名的各项费用、新总额、变化、另一读法的总额，以及承运商写明的应付数和明细之间的 gap），并标出审核员该看的地方。建议只有"解析通过检查""建议人工审核""建议退回承运商"三种，从不决定该不该付。

语言模型（Claude）只说明文字里每个编号的金额是什么：不能写入原文里没有的数字（只能引用编号），给金额的正负号也必须有这笔金额旁边的原文依据（贷记词、括号或紧贴的负号），由代码核对，只有紧贴负号、说不清是分隔符还是贷记的送人工；它也看不到任何预期总额。找数字、检查、算总额、票货汇总、给建议都由代码做。调模型前先遮掉人名和邮箱，另有一步筛查对系统说话的文字。到 Base v1（内部检查点 `mvp-v1.4`），整条流程从头跑到尾，输出有两份接口说明，不需要密钥也能在干净检出上用合成样例跑通。

## 假设（来自客户 11-13 的答复和我们的决定）

- Delta、Invoice Amount、Invoice Dups Removed 是表格估算，不是事实，只作评估基线。
- 费用属于票货；同一辆车上几个订单的同一段说明是一条说明。
- 同一票货里，后一条说明的同一费用取代前一条；不同费用相加。
- BALANCE DUE 金额比前面某金额高 3% 到 7% 时取代它；其他对不上已定关系（倍数、合计、金额加税）的 BALANCE DUE 送人工。
- 金额都是美元；税单列一行，跟着它所在的说明。
- 费用名按客户清单；一个名字对应几个 EDI 代码时全部列出、不替客户选。

同一批第三轮事件出现两个 Recall（上表 94.2% / 96.7%，第四轮里 95.4% / 96.6%），是因为第四轮按新约定重判了其中 51 个事件的标准答案；我们的读法和建议没变，原来的 3 个漏报（一个金额对两项费用）在新答案里不再算该送人工。

目标是 Recall ≥ 95%、FOR ≤ 2%：人工标注集在纠正标签后达到；第四轮新增事件达到，但 6 个阳性说服力弱；第三轮 mock 的 FOR（6.8%）没达到。按真实写法比例加权的 Recall（99.9%）说明不了多少：真实数据最常见的写法（约占 68%）在 mock 里没有阳性事件。

## 进度

计划里 28 项必做工作（185 人时，含本周新增的 Base v1 收敛、跨批次历史、审核界面重做三项）中，21 项已做、等负责人验收，按工时算 65.1%；未验收按 70% 计，完成度 45.6%。调模型累计 117.65 美元（API 价格代理值，非实际账单；上限 145）。
