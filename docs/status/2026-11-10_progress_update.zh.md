## 2. 做法上改了什么（相对 11 月 5 日的计划和设计）

| 改了什么 | 原因 |
|---|---|
| "建议退回"只用于空文本和只有数字的文本，其余需要留意的都送人工 | 只有代码能单独确定的事实才该触发退回；这是项目负责人给第二段定的规则（[规则改动记录](../autorun/rule_changes_leg2.zh.md)） |
| 颜色由 `config/rules.yaml` 里标识的三档严重程度算出，不再计分 | 决定 2.3 可以直接按档表达，少一个要调的阈值 |
| 主张金额按符号相加（贷记为负）后再和 Delta 比 | 按绝对值比会把"该退的读成该补的"也算一致 |
| 默认脱敏从 Presidio 改为词表白名单（**项目负责人还没确认，P-20**） | 实测漏检率 29.0% → 10.9%，没有测到对解析的损害（[对比报告](../deliverables/T10-redaction-comparison/README.zh.md)） |
| 审核界面自建（标准库加 SQLite），不用开源工具 | 评估过的工具做不到按发票展开、按严重程度计数；评估只看了文档（[U1](../deliverables/U1-review-tool-evaluation/README.zh.md)） |
| 基线实验就是"护栏关闭"那一组：一次直接抽取，没有数字表、检查和标识 | 只把检查关掉的话两组看不出差别 |
| 措辞调优的"变差"门槛在每轮之前写定，并以实测的运行间波动为准；5 轮里 4 轮回退 | 落在噪音范围内的变化不能留（[调优记录](../autorun/tuning_log.zh.md)） |
| SKILL 用的真实开发集例子留在 git 忽略的文件里，仓库里放 5 条合成例子 | 真实行不能进仓库 |
| 标注改成 3 个包 × 45 条、其中 15 条公共（共 105 条不同记录），不是"100 条、20 条双人标" | 两三个人可以同时标；任取两个包是 75 条，其中 15 条双人标 |
| S1、H1、U1、K1 计划里按人工估，实际由 CC 做出 | 产出是自主运行里顺带做出来的；仍需要人核对 |
| 读测试集或原始文件在代码层被拒绝，除非项目负责人打开开关 | 只靠 deny 规则盖不住所有路径 |

没有问项目负责人就定的事都在[决定日志](../autorun/decision_log.zh.md)；还没定的在[待决清单](../autorun/pending.zh.md)。

## 8. 已知的问题和限制

- 没有任何一项经过验证，证据都是样本内的。
- 开发集全量的数字来自比样本和 mock 更早的版本。
- 注入检测没达到门槛；改用白名单脱敏后，模型在 mock 上报告的注入变少（18 个，之前 25 到 27 个）。
- 白名单脱敏在合成的个人信息用例上仍漏 10.9%（当初建议的目标是 2%），还会遮住它没见过的费用词。
- 样本 A 上还有一条已知的读错：多付款被读成费用而不是贷记；能修它的措辞因为拉低 mock 结果被回退了。
- 税、币种和查重的处理都建立在等 Jake 回答的假设上；税一律送人工。
- 审核界面有一个叫"批准"的按钮：它只记录审核员本人的决定，但名字接近项目禁止的东西（P-24）。
- 标注包里同一种文本模板最多 2 条，所以不是无偏的频率样本（P-25）；Excel 文件只用程序检查过。
- 调模型的花费到现在是 71.67 美元，上限 110 美元（按 API 标价估算，不是账单）；选做项全做会超上限。
